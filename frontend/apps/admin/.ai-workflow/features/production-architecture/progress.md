- 2026-10-16 T-01: pages read data through the DAL (verifySession with React cache, DTOs without hashes). Repositories are mock (file store) or api (interceptors: request id + Bearer from the session cookie, retries; 404/409 mapped to domain errors). Self-review caught a concurrency bug in the first api-source draft (a shared captured login token) before it shipped: now one client per login. NEXT_PUBLIC_API_URL and lib/api.ts stay temporarily until client forms become Server Actions (T-03…T-05). The cookie E2E assertion is now attribute-based, since Next's cookies().set orders attributes differently.
- 2026-10-16 T-02: three layers: proxy decodes the role from the cookie (optimistic, no secret or DB); requirePermission/authorize in the DAL for pages, handlers and actions; UI hides controls. With only ADMIN/VIEWER both can read every page, so the proxy's role redirect is in place but has no case yet (ready for future routes). Legacy user records without a role map to VIEWER (least privilege).
- 2026-10-16 T-03: login and logout are Server Actions with useActionState / useFormStatus and work without JS. The sliding-window limiter (5 per 15 minutes per email+IP) lives on globalThis because route bundles duplicate modules. Found a real UX issue: React 19 resets forms after an action, clearing the email after a failed login, so the action echoes the non-secret values back as defaultValue. The flaky first draft of the lockout test was a race on the stale alert; it now waits for the reset signal (empty password).
- 2026-10-16 T-04: saveWeekAction does authorize('metrics:write'), validates on the server (dotted field errors), upserts, logs and calls revalidatePath('/'). The ~280-line form is split into pure helpers + table + client island. react-hooks/set-state-in-effect rejected handling the result in an effect, so the result is handled in a client wrapper around the action; this form therefore needs JS (login stays progressive). 'Unsaved' compares numerically. NOTE: apps/*/.env were changed outside this session to DATA_SOURCE=api with API_URL :4000 (a new ../../../backend NestJS app); they were left untouched and verification overrides DATA_SOURCE=mock via the process env.
- 2026-10-16 T-05: create/update/delete are Server Actions (authorize events:write/delete → server zod → DAL → revalidatePath). Deleting an already-deleted event counts as success (idempotent). The form restores submitted values after React's post-action reset. The browser no longer calls any API: NEXT_PUBLIC_API_URL left the env schema; the value still in the user's .env is simply unused.
- 2026-10-16 T-06: Server Actions and zod schemas now return message keys (+ ICU values such as {minutes}), translated by useMessage on the client, so the mock API's 400 details are stable codes. The proxy runs the auth/role checks on the locale-less path, then next-intl. Login's default next is the localized home.
- 2026-10-16 T-07: a dark screenshot exposed a shared bug: the Dialog backdrop used bg-foreground/40, which turns light in dark mode. Added a semantic 'overlay' token (black in both themes; the token tests enforce light+dark coverage) and the Dialog uses bg-overlay/50.
- 2026-10-16 T-08: Next invokes onRequestError twice for a layout render error (same digest); kept as is, so group by digest.
